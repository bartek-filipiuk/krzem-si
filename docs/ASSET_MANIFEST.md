(no third-party models, textures or HDRIs). Repository licence: not chosen yet (see README), so
they are covered by the same terms as the rest of the repo. Tools: Blender 5.2.2 LTS (build
`d13f752e3b9c`), Cycles on OptiX (RTX 3070 Laptop), glTF exporter bundled with Blender; 2D finishing
with Python 3.10 + Pillow 10.0 + numpy (`tools/blender/compose.py`). Seeds: chunk `--seed 14`,
per-piece material jitter `default_rng(1000)`, Cycles seed 0 (default), poster dither `default_rng(14)`.
Commands and run times: `tools/README.md`. `B` = `~/tools/blender/blender -b --factory-startup -P`.

Source mesh: the 1.31M-triangle high-res surface is rebuilt from the seed on every run and never
written to disk; `--blend` saves the runtime scene to `tools/blender/src/silicon_chunk.blend` if a
`.blend` is ever needed. Nothing large is kept out of git.

Note 1, tangents: the GLBs ship without TANGENT (saves 743 KB on 2K, 311 KB on 1K, needed to stay
under 3 MiB / 1 MiB with the fine grain in the maps). Three.js derives the tangent frame per pixel;
checked against Cycles in `docs/qa/assets/NOTES.md`. The files in the repo were exported with
tangents and then stripped by a lossless repack (only the TANGENT accessor removed); the script now
exports with `export_tangents=False`, which gives the same data or fewer vertices.

Note 2, environmentIntensity: Three.js has no interreflection, so concave faces only see the dark
studio. At the A2 pose (180 deg) 1.35 matched the poster; at the A3 pose (120 deg) the value is
1.65: mean chunk luminance canvas vs poster 83.7 vs 84.0 (desktop) and 93.9 vs 93.7 (mobile) of 255
(`docs/qa/after/capture-nvidia.json`, key `handover`).
